# 排查与已知限制

## 胶囊不出现

| 可能 | 怎么确认 | 处理 |
| --- | --- | --- |
| 没有正在跑的任务 | 让它跑一轮 Codex / DSH，看托盘图标是否还在 | 空闲时它**本来就完全不显示**，这是设计 |
| 托盘里关掉了「显示控件」 | 右键托盘 → 看 `显示控件` 有没有勾 | 勾上 |
| 装了两个实例 | 任务管理器里数 `codex-widget.exe` 的个数 | 只留一个；卸载旧版本或结束多余进程 |
| 数据源读不到 | 用 `CODEX_WIDGET_HOME` 指向假数据跑一遍 | 见 [getting-started](getting-started.md#不打扰真实-codex-地调试) |

## 完成态不消失

- 正常行为是**5 分钟**后淡出，没到点不会走；
- 想立刻收起就**双击**它；
- 如果超过 5 分钟还在：这是 0.6.0 及更早版本的已知问题——全屏提醒盖住主窗口时，Chromium 会节流窗口里的长定时器，5 分钟的 `setTimeout` 会迟到。0.6.1 起改成"截止时间 + 500ms 心跳比对"，最多迟到一分钟。

## 全屏提醒不出现

- 阈值在托盘里：`关闭` / `≥ 3 分钟` / `≥ 10 分钟`，先确认不是 `关闭`；
- 只有**超过阈值**的那一轮结束才会触发，短任务不会；
- 它出现时你若正好在打字，那一下按键会把它关掉并**被它吃掉**——这是"任意键关闭"的代价。

## 通知署名是 "Windows PowerShell"

只在开发态（`npm run app:dev`）出现：进程没有注册的 AppUserModelID，Windows 会归到启动它的 shell 名下。用安装包装好后署名与图标都正确（`Codex Widget` + 自己的图标）。

## 已知限制

- **不是官方 API。** Codex 侧读的是它自己写的日志，属于私有格式。已验证于 Codex CLI `0.169.0-alpha.11.1` + VSCode 扩展 `26.1111.21308`，并在 100 个真实会话、单个 27MB 的 rollout 文件上做过回归。上游改格式时这里会读不到——它会显式降级为"什么也不显示"，而不是乱猜。
- **"疑似卡住"是启发式。** 15 分钟无新事件即视为停滞。一个长思考、无工具调用的回合有可能被误判为暗色；事件一到就恢复呼吸。
- **只在 Windows 上验证过。** 代码里没有 Windows 特有的硬编码，但 macOS / Linux 的托盘、开机自启、通知行为未测试。
- **拖动是 JS 实现的**（跟着指针算偏移再 `setPosition`），不是系统原生的窗口拖动。这样双击才能同时存在；代价是极快甩动时可能有一两帧滞后。
- **同一来源最多显示一行**：多个并发只体现为 `×N`，展开看单个任务目前不做。
- **DSH 侧依赖投影缓存的字段名**（`turnBoundary` / `sessionStats` 等）。DSH 升级若改了投影结构，需要在 `src-tauri/src/dsh.rs` 里同步。读不到时会静默降级，不会误报。
